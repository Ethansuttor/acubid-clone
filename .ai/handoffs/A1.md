## The rules the engine enforces

These come from the comparison table in
[19-real-estimate-acceptance.md](../19-real-estimate-acceptance.md):

- **Counted quantities have zero tolerance.** There is no "close enough" to 47
  receptacles; a one-device miscount fails.
- **Measured quantities use the tolerance the estimator recorded in the job
  file.** The engine never picks one. A job file without
  `measurementTolerances` is refused rather than defaulted.
- **A matching grand total is not a pass.** When every total is within
  tolerance but a line is not, the engine sets `offsettingDifferences` and the
  report says in as many words not to accept on the strength of the total.
  Offsetting material and labor errors are the failure mode most likely to be
  waved through.
- **Unpriced quantity and known unsupported scope are open items**, and an open
  item yields the `open-items` verdict with a nonzero exit code even when every
  number agrees. The engine reads open items from the app's own
  `EstimateIssue` list rather than a separate judgement.
- **A missing or unexpected line is a discrepancy**, not a rounding curiosity.
- **A synthetic run says so.** The report prints the provenance banner and
  "cannot establish real-estimate acceptance (gate G5)"; a passing synthetic
  run reports "the harness works. Real acceptance remains pending."

The runner refuses to reconcile a job file marked `real` against fixture
numbers (exit 2). That combination would manufacture a passing report for a job
nobody ran; the real path needs the A2 workspace export.

## Commands and exact results

    npm run acceptance     synthetic-fixture: 8/8 lines, 3/3 totals, verdict "reconciled", exit 0
    npx vitest run tests/acceptance    19 tests passed

The synthetic run computes its actual side with `layerQuantities`,
`extendEstimate`, `materialRollup`, `estimateTotals` and `summarize` — the
application's own functions. The harness deliberately contains no estimating
arithmetic of its own: a harness that re-implements the math proves only that
it agrees with itself.

## What this does not do

- It does not read a real workspace. The actual side currently comes from the
  repository fixture; A2 supplies an exported real estimate.
- It reconciles line quantities, material, labor and three totals. It does not
  yet compare intermediate commercial subtotals, breakdown groups, proposal or
  Excel output, or frozen-revision behavior — all required by A2 steps 5–7.
- It has no CSV reader; the job file is JSON. Add CSV only when a real export
  arrives in that form, so the parser is written against real data.
