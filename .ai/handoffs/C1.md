## Contract decisions worth knowing before dependent work

- **Error codes are the contract; message text is not.** Callers branch on
  `code`. `aborted` is distinct from `io-failed` precisely so a cancelled job is
  never displayed as a failed save.
- **`exclusiveWorkspaceLock` is a capability, not an assumption.** The browser
  adapter derives it from Web Locks, which coordinate tabs in one
  origin/profile only. The desktop adapter must answer for itself.
- **Compound operations are first-class**: `replaceAssemblyItems`,
  `exportBundle`, `restore`, `withExclusiveWorkspace`. They exist because they
  cannot be safely composed from smaller calls.
- **Restore refuses a non-empty destination with `occupied`** and validates the
  whole graph before the first write. Both adapters and the contract suite
  enforce this.
- **No credential read exists.** `desktop/contracts.ts` offers
  `credential.set`, `credential.clear`, `credential.status` and nothing else; a
  test asserts no read-shaped operation was added.
- **`AI_LIMITS` mirrors the shipped route bounds** (48 candidates per run, 12
  crops per request, 256 px crops, 2 MB verification body, 40 sheets). The route
  validator `validateVerifyRequest` remains the enforcing authority server-side;
  these constants must not drift from it.
- **Adapter selection is explicit registration** (`setWorkspaceStorage`,
  `setAiTransport`), not a lazy import, so Node tests and the Electron main
  process can load the seam without pulling in IndexedDB. `aiTransport()`
  returning `null` means local-only, and callers must say so.

## Remaining failures or missing inputs

- The browser storage adapter now runs the full contract suite against a live
  IndexedDB (`fake-indexeddb`, added as a devDependency — the one shared
  manifest change in this task). Web Locks are Node 24's own implementation, so
  the workspace lock and the per-mutation database lock are exercised for real;
  only IndexedDB and `localStorage` are substituted. A deliberate sabotage of
  one error mapping was confirmed to fail exactly one contract test, so the
  suite is not vacuously green.
- What that still does not cover: real browser storage quotas, eviction,
  cross-tab behavior with genuinely separate tabs, and Blob handling
  differences between `fake-indexeddb` and a real browser engine. Those remain
  E2E territory.
- `createBrowserAiTransport` now has 13 tests with `fetch` stubbed: 401/503/400/
  502 map to `unauthorized`/`unavailable`/`invalid-input`/`io-failed`, an
  over-limit batch is refused before any request is issued, decisions for crops
  that were never sent and malformed decisions are dropped rather than trusted,
  and an aborted call reports `aborted`. No request leaves the machine and no
  paid call is possible.
- `AI_LIMITS` is pinned to its enforcing code: crop count and crop edge are
  checked against the real `validateVerifyRequest`, the per-run ceiling against
  the pipeline's `MAX_AI_CROPS`/`AI_BATCH_SIZE`. The 2 MB body cap and the
  40-sheet cap are literals inside route handlers that cannot be imported
  outside the Next.js server runtime, so those two are asserted against the
  route source and labelled as such in the test — the routes are not executed.
- No E2E, packaged desktop, or real-estimate evidence is claimed by this task.
